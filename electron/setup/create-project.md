# Create the Project

This stack uses **Angular CLI as the root of the project**. The renderer is a normal Angular app, and the `electron/` folder is added by hand inside it afterwards.

---

## Prerequisites

- Node.js 20 LTS or higher
- npm 10+
- Angular CLI installed globally: `npm install -g @angular/cli`

---

## 1. Create the Angular Project

```bash
ng new <project name> --routing --style=scss
cd <project name>
```

When asked about SSR (Server-Side Rendering), answer **No** — Electron doesn't need it.

This already leaves `package.json`, `angular.json`, `tsconfig.json`, and `src/` ready. Everything else is added on top of this, without recreating anything.

---

## 2. Target Folder Structure

This is the structure you're building towards over the next steps:

```bash
📂<project name>                 # root = Angular CLI project
├─ 📄 angular.json
├─ 📄 package.json               # single package.json, everything lives here
├─ 📄 tsconfig.json              # generated by Angular CLI — belongs to the renderer, do NOT touch its moduleResolution
├─ 📄 tsconfig.app.json
├─ 📄 tsconfig.spec.json
├─ 📂 src                        # renderer (Angular)
│  ├─ 📂 app
│  ├─ 📄 electron-api.d.ts       # types for the contextBridge
│  └─ 📄 ...
├─ 📂 electron                   # added by hand, Electron's code
│  ├─ 📄 tsconfig.json           # independent, explicit CommonJS
│  ├─ 📄 main.ts
│  ├─ 📄 preload.ts
│  ├─ 📄 data-source.ts
│  ├─ 📂 entities
│  │  └─ 📄 user.entity.ts
│  └─ 📂 services
│     └─ 📄 user.service.ts
└─ 📂 dist
   ├─ 📂 <project name>          # output of `ng build` (renderer)
   └─ 📂 electron                # output of `tsc` (main/preload)
```

> [!IMPORTANT]
> The root `tsconfig.json` belongs to Angular CLI (it uses `moduleResolution: "bundler"` or similar, meant for its own compiler). The `electron/tsconfig.json` is **independent** — it does not extend it. It needs explicit `CommonJS` and must never be mixed with the renderer's configuration.
