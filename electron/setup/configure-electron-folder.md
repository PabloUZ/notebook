# Configure the Electron Folder

The `electron/` folder is not generated by any CLI — it's added by hand inside the Angular project, with its own independent TypeScript configuration.

---

## 1. Create the Folder Structure

```bash
mkdir -p electron/entities electron/services
```

---

## 2. `electron/tsconfig.json`

```json
{
  "compilerOptions": {
    "target": "ES2021",
    "module": "CommonJS",
    "moduleResolution": "node",
    "outDir": "../dist/electron",
    "rootDir": ".",
    "esModuleInterop": true,
    "experimentalDecorators": true,
    "emitDecoratorMetadata": true,
    "useDefineForClassFields": false,
    "strict": true,
    "skipLibCheck": true,
    "resolveJsonModule": true,
    "types": ["node"]
  },
  "include": ["**/*.ts"]
}
```

| Option | Why it matters |
|---|---|
| `module: "CommonJS"` | The main/preload processes run in Node, not in a bundler |
| `experimentalDecorators` / `emitDecoratorMetadata` | Required by TypeORM and class-validator decorators |
| `useDefineForClassFields: false` | **Critical.** Without this, TypeORM/class-validator property decorators break silently on ES2022+ targets |
| `outDir: "../dist/electron"` | Keeps compiled output next to the renderer's build output under `dist/` |

> [!IMPORTANT]
> This `tsconfig.json` does **not** extend the root one — see the note in [Create the Project](./create-project.md).

Since this is CommonJS, imports **without an extension** work without any extra configuration:

```typescript
import { UserService } from './services/user.service'; // no .js needed, works normally
```
